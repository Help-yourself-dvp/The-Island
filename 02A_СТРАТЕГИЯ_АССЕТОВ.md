# 02A — СТРАТЕГИЯ ГРАФИЧЕСКИХ И ЗВУКОВЫХ АССЕТОВ

## 1. ПРИНЦИП

Новый проект НЕ является procedural-only игрой.

Опыт предыдущего проекта SKYFORGE показал, что требование создавать все модели персонажей, деревьев, зданий и props непосредственно из примитивов Three.js приводит к неудовлетворительному визуальному результату и тратит слишком много времени AI-разработчика на производство слабого арта.

Поэтому новый проект использует HYBRID ASSET PIPELINE.

GAME-READY EXTERNAL ASSETS:
- characters;
- trees;
- bushes;
- rocks;
- buildings;
- furniture;
- farm props;
- town props;
- animals;
- tools.

CODE / THREE.JS:
- world placement;
- gameplay;
- terrain;
- water;
- sky;
- lighting;
- shadows;
- particles;
- feedback;
- UI;
- procedural variation;
- animation control.

Цель:

не доказать, что весь арт можно создать кодом.

Цель:

сделать красивую законченную игру законным и воспроизводимым способом.

============================================================
2. ЛИЦЕНЗИОННЫЙ ПРИНЦИП
============================================================

Предпочтительная лицензия:

CC0 / Public Domain.

Она предпочтительна потому, что проект потенциально может распространяться через Google Play и другие магазины.

Каждый используемый внешний asset должен иметь проверяемое происхождение и разрешение на соответствующее использование.

Нельзя считать:

FREE

синонимом:

FREE FOR COMMERCIAL USE.

============================================================
3. ДОПУСТИМЫЕ ЛИЦЕНЗИИ
============================================================

Приоритет:

1. CC0 / Public Domain.
2. Другие явно permissive licenses, если агент проверил требования.
3. Attribution licenses только если требования реально выполнимы и корректно документированы.

Не использовать без отдельного решения:

NonCommercial;
NoDerivatives;
Editorial Only;
unknown license;
ambiguous license;
assets без источника;
ripped assets;
контент чужих игр.

Quaternius

Kenney

============================================================
6. GITHUB-FIRST RESEARCH
============================================================

Среда AI-agent может иметь ограниченный доступ к обычным websites, но доступ к публичным GitHub repositories.

Поэтому перед тем как просить пользователя вручную скачивать packs:

САМОСТОЯТЕЛЬНО ИССЛЕДУЙ GITHUB.

Ищи:

- game-ready asset packs;
- CC0;
- stylized;
- low-poly / optimized mid-poly;
- glTF;
- GLB;
- animated characters;
- nature packs;
- town packs;
- farm packs.

Не использовать случайный repository только потому, что он найден поиском.

Проверить license и provenance.

============================================================
7. ЕСЛИ НУЖЕН РУЧНОЙ DOWNLOAD
============================================================

Если лучший pack доступен только на website, который AI-agent не может скачать:

НЕ заменяй его автоматически худшим asset.

Сообщи пользователю:

1. точный URL страницы;
2. точное название pack;
3. автора;
4. лицензию;
5. какой файл/архив скачать;
6. куда загрузить его в GitHub.

Пользователь не должен разбираться в форматах внутри архива.

Рекомендуемая папка:

incoming-assets/

Пользователь загружает туда оригинальный ZIP.

Дальнейшую работу выполняет agent.

============================================================
8. НЕ ТРЕБОВАТЬ BLENDER ОТ ПОЛЬЗОВАТЕЛЯ
============================================================

Если source pack содержит:

FBX;
OBJ;

не говорить автоматически:

«пользователь должен открыть Blender и экспортировать GLB».

Сначала исследовать автоматический conversion pipeline.

Допустимы:

CLI tools;
Node tools;
Python tools;
GitHub Actions;
headless conversion environment.

Если единственный разумный способ действительно требует Blender:

рассмотреть возможность запуска Blender headless в CI/agent environment.

Пользователь не должен устанавливать Blender локально.

============================================================
9. RUNTIME FORMAT
============================================================

Предпочтительный runtime format:

GLB / glTF.

Причины:

Three.js support;
materials;
animations;
skins;
compact packaging.

Production game не должна загружать asset с Internet.

GLB/glTF находятся внутри APK.

============================================================
10. SOURCE И RUNTIME ASSETS
============================================================

Не смешивать исходные архивы с optimized production assets.

Пример:

incoming-assets/
  source-pack.zip

assets-src/
  ...

public/assets/models/
  optimized-tree.glb

или другая архитектура, выбранная проектом.

Игровой bundle должен использовать оптимизированные production assets.

============================================================
11. НЕ КЛАСТЬ ВСЁ В APK
============================================================

Если pack содержит 200 моделей:

не включать автоматически все 200.

Выбрать только реально используемые.

Цель:

маленькая согласованная библиотека.

============================================================
12. STYLE CONSISTENCY
============================================================

Самый важный критерий после лицензии:

ЕДИНЫЙ СТИЛЬ.

Плохо:

photogrammetry rock
+
cartoon tree
+
voxel character
+
realistic house.

Хорошо:

несколько packs с:

сходными proportions;
soft shapes;
сходной детализацией;
сходной saturation;
сходным material response.

============================================================
13. ЦЕЛЕВОЙ ART STYLE
============================================================

Игра должна выглядеть как polished stylized mobile game.

Ориентиры:

- округлые формы;
- чистые silhouettes;
- мягкие края;
- приятные цвета;
- читаемые персонажи;
- умеренная детализация;
- хорошая работа света.

Не стремиться к photorealism.

Не делать primitive/prototype look.

============================================================
14. ПЕРВЫЙ ASSET RESEARCH
============================================================

До реализации production world AI-agent должен найти минимум 3 возможных asset-family стратегии.

Для каждой предоставить:

- источники;
- licenses;
- formats;
- приблизительный размер;
- visual style;
- categories;
- наличие animations;
- необходимость conversion;
- mobile suitability.

Например:

OPTION A:
почти полностью один Quaternius family.

OPTION B:
Kenney environment + отдельный compatible character.

OPTION C:
проверенный GitHub CC0 pack family.

Не подключать все три.

============================================================
15. ASSET AUDITION SCENE
============================================================

Перед строительством всей игры создать техническую ART AUDITION SCENE.

Она должна содержать одновременно:

- player candidate;
- 2–3 trees;
- bush;
- rock;
- building piece;
- crate/barrel;
- ground;
- water fragment;
- directional light;
- shadows.

Цель:

увидеть, сочетаются ли assets ВМЕСТЕ.

Не оценивать tree отдельно на website thumbnail.

============================================================
16. ART AUDITION APK
============================================================

Если pipeline позволяет, собрать audition scene в APK.

Пользователь оценивает её непосредственно на Honor Magic 8 Pro.

Проверить:

- стиль;
- масштаб;
- sharpness;
- colors;
- shadows;
- FPS.

Только после принятия art family строить вокруг него игру.

============================================================
17. НЕЛЬЗЯ ПОВТОРИТЬ ОШИБКУ SKYFORGE
============================================================

Не строить сначала всю игру с временными ужасными primitive assets с обещанием:

«потом заменим».

Ключевой visual language должен быть подтверждён РАНО.

Первый vertical slice должен уже использовать выбранный production art family.

Temporary debug boxes допустимы только локально во время разработки.

============================================================
18. NATURE PACK
============================================================

Для первого острова нужен ориентировочно следующий минимальный набор.

TREES:
4–6.

BUSHES:
3–5.

ROCKS:
5–8.

SMALL PLANTS:
5–10.

LOGS/STUMPS:
3–5.

GRASS:
1–3 base assets или shader/instancing.

FLOWERS:
несколько вариантов.

Не нужно 100 уникальных trees.

============================================================
19. VARIATION
============================================================

Из малого числа моделей создавать diversity:

rotation;
scale;
mirroring, если корректно;
material tint;
grouping;
density;
biome placement.

Не создавать hundreds draw calls ради diversity.

============================================================
20. CHARACTERS
============================================================

Character pack критически важен.

Предпочтительно найти одного rigged stylized character family, содержащего:

player;
workers;
visitors

или легко создаваемые variations.

Минимальные необходимые animations:

IDLE
WALK
RUN
WORK/CHOP
CARRY или подходящая upper-body pose
PICKUP/INTERACT
SHORT CELEBRATION.

Дополнительно:

MINE
WATER/PLANT
COOK

желательны, но не обязательны сразу.

============================================================
21. НЕ АНИМИРОВАТЬ ГЕРОЯ ПРИМИТИВАМИ
============================================================

Не использовать procedural humanoid из:

boxes;
capsules;
spheres

как production main character.

Для debug допустимо.

Для production vertical slice нужен нормальный game-ready character.

============================================================
22. ANIMATION ADAPTATION
============================================================

Если character pack не содержит точной animation:

не обязательно отвергать весь pack.

Можно:

- переиспользовать близкую;
- blend;
- изменить playback speed;
- добавить held tool;
- использовать simple procedural upper-body adjustment.

Но базовая locomotion должна быть authored animation.

============================================================
23. WORKER VARIATION
============================================================

Не нужны 20 уникальных персонажей.

Один общий rig может создавать workers через:

- shirt color;
- hat;
- apron;
- backpack;
- tool.

Это предпочтительнее случайных персонажей из разных packs.

============================================================
24. BUILDINGS
============================================================

Предпочтительно использовать modular stylized building kit.

Нужны элементы:

walls;
roof;
doors;
windows;
wood structures;
fences;
market stall;
farm shed;
restaurant;
town props.

Если готовой модели каждого здания нет:

собирать здания из согласованных модулей.

Это лучше, чем procedural primitive architecture.

============================================================
25. BUILDING STAGES
============================================================

Для construction progression удобно иметь modular assets.

RUIN:

часть элементов скрыта/сломана.

REPAIR:

появляется foundation/walls.

COMPLETE:

roof/sign/details.

Не обязательно иметь три отдельные модели здания.

============================================================
26. PROPS
============================================================

Небольшие props дают много визуального качества.

Нужны:

crate;
barrel;
sack;
bench;
table;
chair;
lamp;
sign;
tools;
cart;
basket;
food crates.

Но props должны принадлежать общей стилистике.

============================================================
27. FARM ASSETS
============================================================

Нужны:

farm plots;
soil;
wheat;
carrot;
tomato;
apple tree или fruit-compatible tree;
barn props;
basket;
fence;
scarecrow.

Если часть отсутствует:
допустимо создать простые secondary props кодом.

Но ключевые объекты должны выглядеть production-ready.

============================================================
28. ANIMALS
============================================================

Для первой фермы достаточно:

chicken.

Если есть compatible stylized animal pack:

можно позже добавить.

Не делать procedural sphere-with-legs production animals.

============================================================
29. MATERIALS
============================================================

Если game-ready pack уже имеет качественные stylized materials:

не заменять их автоматически.

Сначала посмотреть на целостный результат.

При необходимости унифицировать:

roughness;
metalness;
color saturation;
environment response.

============================================================
30. PBR TEXTURES
============================================================

Не использовать тяжёлые 4K/8K textures в mobile game без причины.

Обычно:

512–1024 достаточно.

Крупная hero surface:
до 2048 при доказанной пользе.

============================================================
31. HDRI
============================================================

HDRI является отдельным инструментом lighting, а не обязательным asset.

Можно провести A/B:

procedural/simple environment
vs
CC0 HDRI.

Не использовать HDRI, если он разрушает stylized art direction.

============================================================
32. POLY HAVEN
============================================================

Poly Haven полезен для:

HDRI;
отдельных textures/material references.

Не использовать по умолчанию их high-detail photogrammetry models для мобильной stylized игры.

Модель размером сотни MB не является автоматически качественнее для нашего проекта.

============================================================
33. AUDIO ASSETS
============================================================

В новом проекте разрешены легальные external SFX/audio.

Предпочтение:

CC0.

Нужны категории:

footsteps;
wood chop;
tree fall;
pickup;
delivery;
coins;
build;
farm;
cooking;
water;
birds;
crowd ambience.

Не загружать огромную audio library целиком.

============================================================
34. MUSIC
============================================================

Music licensing проверять особенно внимательно.

Нельзя считать royalty-free автоматически CC0.

Для первой версии допустимо:

не использовать music

или использовать только ясно лицензированный track.

============================================================
35. OPTIMIZATION
============================================================

После импорта проверить:

mesh count;
draw calls;
materials;
texture size;
animations;
unused nodes.

Удалять неиспользуемое.

Использовать instancing для массовых одинаковых environment objects там, где это совместимо с asset.

============================================================
36. COLLIDERS
============================================================

Render mesh не обязан быть collider mesh.

Для:

trees;
rocks;
buildings

использовать простые collision volumes.

Не строить collision по каждой ветке дерева.

============================================================
37. LOD
============================================================

Для большого количества природы при необходимости:

LOD или distance culling.

Но не создавать сложную систему заранее, если производительность уже достаточна.

============================================================
38. ASSET CACHE
============================================================

GLB загружается один раз.

Повторяющиеся instances создаются из cached source.

Не загружать один файл заново для каждого дерева.

============================================================
39. FAILURE RULE
============================================================

Если подходящего легального asset найти не удалось:

НЕ переходить автоматически к ужасному production primitive.

Варианты:

1. найти другой pack;
2. попросить пользователя вручную скачать конкретный рекомендованный pack;
3. создать простой secondary asset кодом;
4. временно оставить feature вне vertical slice.

Качество важнее галочки.

============================================================
40. ЧТО ДОЛЖЕН СДЕЛАТЬ AI В ПЕРВОМ ASSET-ЭТАПЕ
============================================================

До создания полноценного gameplay:

1. Изучить доступные GitHub sources.
2. Определить 3 asset-family candidates.
3. Проверить licenses.
4. Проверить formats.
5. Проверить animations.
6. Оценить mobile suitability.
7. Составить отчёт.
8. НЕ строить весь проект до принятия visual direction.

Если один кандидат явно существенно лучше остальных и полностью соответствует лицензии/форматам, можно рекомендовать его пользователю, но не скрывать альтернативы.

============================================================
41. ЕСЛИ AGENT НЕ МОЖЕТ СКАЧАТЬ
============================================================

Дать пользователю конкретную инструкцию.

Не:

«скачайте какой-нибудь Quaternius pack».

А:

«Откройте URL X.
Нужен pack Y.
License Z.
Скачайте ZIP.
Загрузите ZIP без распаковки в incoming-assets/».

Пользователь делает только это.

============================================================
42. ART ACCEPTANCE GATE
============================================================

До строительства Zone 1 нужно ответить:

[ ] Нравится ли player?
[ ] Нравятся ли trees?
[ ] Нравятся ли rocks?
[ ] Сочетаются ли building и nature?
[ ] Масштаб выглядит естественно?
[ ] Lighting делает assets лучше?
[ ] Нет ли primitive/prototype look?
[ ] Работает ли на Honor Magic 8 Pro?

Если ответ пользователя:

«выглядит жутко»

НЕ продолжать строить всю игру.

Исправить art direction сначала.
